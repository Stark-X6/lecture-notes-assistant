# 现实票务机制与本项目的取舍

调研整理于 2026-10-23。不同平台、活动和车次规则不同，公开业务说明也不等于内部技术实现。下面将可确认的公开事实与课堂模型分开说明。

## 1. 查询到余票，不代表已经占票

12306 用户须知说明，查询和提交订单之间其他用户也可能订票，提交时需重新判断。因而现实竞争不能只比较“刷新多快”，还应看提交、确认和付款是否完成。

来源：[12306 用户须知](https://kyfw.12306.cn/otn/gonggao/usersNeedToKnow.html?linktypeid=reg)。本项目采用查询、占位、确认三步，查询携带时间戳但不锁库存。该页面其他条目的时间和限制可能有历史变化，本项目没有直接照搬。

## 2. 候补和缺货提醒是不同机制

12306 官方候补说明将候补兑现与订单生效先后关联，并包含预付款和兑现规则。反复刷新并不会在同一既定队列中自动提升顺序。大麦公开帮助中的缺货登记则用于有票时发送提醒，提醒本身不等于完成购票。

来源：[12306 候补购票服务说明](https://mobile.12306.cn/otsmobile/h5/otsbussiness/houbuRules/houbuRules.html)、[大麦缺货登记帮助](https://help.damai.cn/helpPage.htm?pageId=34)。

本项目“先售后候补”按服务器登记生效顺序递补。为控制课程范围，只处理单张票，没有实现候补预付款、多车次组合和多人整单兑现，因此不能视为 12306 的复刻。

## 3. 账号多不一定等于可买票的人多

部分实名演出按观演人证件限制购票，多个账号给同一人下单仍可能重复。以猫眼公布的 2024 年许嵩郑州场页面为例，其中涉及实名限购、跨平台重复和退票规则。这是具体活动的历史样本，不能推及所有演出。

来源：[该场演出公开详情](https://show.maoyan.com/detail/337784)。

本项目分别建模账号、购票人和设备。程序账号可归属于同一个人；分配资格与有效持票均按人去重。设备在本版与程序购票人分组对应，尚未模拟多人共用设备或一人跨多个设备。

## 4. 未支付释放和已支付退票可以采用不同回流方式

大麦协议涉及订单支付、超时取消和异常订单；具体支付期限应以订单及活动说明为准。上述猫眼活动页面还展示了退票集中后再次销售的做法。不能把某场活动的固定期限推广为所有平台统一规则。

来源：[大麦订票服务条款](https://help.damai.cn/helpPage.htm?pageId=101)、[活动规则样本](https://show.maoyan.com/detail/337784)。

本项目取消未支付占位或付款超时时立即释放；已支付退票先进入待回售池。批次从第一张退票起计时，届时统一放回，后进入该批的票等待时间会更短。时间、概率可调，都是实验参数。

## 5. 高频自动化、排队和防护会改变服务体验

武汉交通部门转载的铁路采访提到异常登录、订票排队和候补响应等现象；公开信息不能确定内部阈值和完整识别算法。上海政府发布的公安案例还涉及自动点击和多设备购票，说明现实自动化不只是一种程序形态。

来源：[铁路相关采访，2025-01-22](https://jtj.wuhan.gov.cn/jtzx/zwdt/202501/t20250122_2524043.shtml)、[上海公开公安案例，2026-07-31](https://www.shanghai.gov.cn/nw31406/20260731/f553809c970d477f85f0c6f69fd51ffa.html)。

本项目用有限服务通道模拟排队；行为防护观察账号、购票人、设备的一秒请求计数，慢处理或拒绝超阈值请求。阈值为教学构造，正常群众和操作者连续点击也可能受影响。群组标签只用于安排行为和计算结果，防护不能直接凭标签识别“程序”。

## 课程可以证明什么

可以展示：在明确假设下，改变自动化行为、身份数、服务容量和分配规则，结果如何变化。可以观察公平性与等待、误伤、资源消耗之间的取舍。

不能据此宣称某现实平台必能被突破，某平台实际处理能力是多少，或者某防护能完全识别程序。本版没有真实票务接口、真实网络负载、生产数据库和真实身份系统。所有数值结论都须同时给出配置、样本数和上述边界。
