# 听课笔记助手 v0.9.1 工程质量复核

2026 年 11 月 25 日。复核基线为 v0.9.0（`53bc04a`）。在独立检出中重跑该版本原有的 113 项单元测试，全部通过。随后从学生补写、恢复、核对笔记和团队交付源码的实际操作出发，补测了原有断言没有覆盖的组合。优先检查可能丢失正文或误报成功的路径，其次检查跨课堂定位、Markdown 层级和交付包可重建性。

## 在 v0.9.0 上复现的缺陷

| 需求与场景 | 基线实际结果 | v0.9.1 的验收结果 |
| --- | --- | --- |
| F09、A05 · 某节采用补充后恢复到采用前的旧版，重启并重交相同选区 | 历史成功回执仍占用该来源，已撤回的小节补不回来 | 按各小节当前来源和待审候选核对回执。被撤回的内容能重新提交，其他小节保留的同源内容不重复写入。 [分节回执](../electron/chapter-supplement.cjs) |
| F09、N03 · 原文含“不需要核查证件”，再采用“需要核查证件。” | 子串匹配把相反结论当作重复，新增来源已登记，肯定句却未出现 | 只把独立的相同段落视为重复。原笔记和新增陈述分别落笔，代码或公式中的文字也不会替代正文。 [正文合并](../electron/markdown-prose.cjs) |
| F10、N02 · 兼容服务传来可解析的 JSON 后断流，缺少完成信号 | 任务显示成功并产生新笔记版本 | 任务失败、笔记版本保持原值；原任务收到正常结束信号后可重试写入。支持以 `[DONE]` 结束的兼容网关。 [流响应](../electron/text-response.cjs) |
| F10、N07 · 在暂停 AI 的课次中重试后台任务，再提交另一门课的任务 | 暂停的任务占住队首，即使后台空闲，另一门课仍持续排队 | 另一门课先完成。暂停任务保持排队和零次尝试，恢复后执行一次。 [队列调度](../electron/provider.cjs) |
| F07、A04、C08 · 打开共享笔记中的旧课堂引用，引用原话已经被修订 | 跳到了正确的课堂和时间，但页面只展示最新文本，无法核对写笔记时的说法 | 在目标段落显示引用原话与当前转录及可用版本号。旧引用缺少正文时，可用转录修订历史恢复；原笔记的冻结来源保持可查。 [转录对照](../src/TranscriptPanel.tsx) |
| F07、G10 · 模型在一节的正文中写了两个来源标识，结构化结果只声明其中一个 | 正文显示了两页的合并页码，来源列表却只有一页 | 完整声明才显示对应位置。不完整的混合清单或区间标记为“部分引用待核对”，读者可以核对本节声明的来源。 [引用解析](../electron/model-citations.cjs) |
| F09、A05 · 将手动创建的小节挂到后来创建的父节下，并从课程和课堂分别导出 | 界面展示了父子关系，导出却按创建顺序把两节写成同级标题，正文标题也可能跳出小节 | 两个入口按同一棵章节树输出，正文标题嵌在所属小节内，代码示例保留原样。 [标题树](../electron/presentation.cjs) |
| Windows 源码交付 · 运行交付脚本，解压 ZIP，加载文本服务配置 | ZIP 内文件的哈希校验通过，解压后的源码因缺少 `electron/text-providers.json` 无法加载 | 显式包含必需的配置文件，仍排除本地临时 JSON。解压后的源码实际完成了配置加载和生产构建。 [交付脚本](../scripts/package-delivery.py) |

## 可复查的证据

执行环境为 macOS 27.2.1（arm64）、Node 25.9.0 和 Electron 45.2.3。修复后完整单元测试为 122/122。macOS 打包版通过章节增补、课堂标签与引用、课程空间、服务商切换和桌面冒烟五组验收脚本。八条缺陷按业务行为计数。

- 分批恢复及原文保护由 [章节补充回归](../tests/chapter-supplement.test.cjs) 和 [选页整理回归](../tests/note-scope.test.cjs) 覆盖，使用合成课堂、真实 SQLite 快照及已保存的版本。
- 中断、重试和其他课程的调度由 [文本任务回归](../tests/text-settings.test.cjs) 验证。兼容服务使用本地构造的 HTTP 响应，断流用例检查任务状态和笔记版本。
- [桌面引用测试](../tests/classroom-citations-desktop.cjs) 从笔记标签实际点击来源。[引用和导出测试](../tests/real-note-format.test.cjs) 核对部分声明、手动层级及代码内容。
- `node tests/delivery-source.cjs` 运行实际交付脚本、解压 ZIP 并加载设置模块。另在完整解压源码上使用本项目已安装的依赖执行了 `npm run build`。占位的 Windows 可执行文件只用于满足打包输入条件，未在 Windows 上做安装或启动验收。

## 仍需单独验收的内容

**生成内容的准确性（N03、G10、A04）仍有缺口。** 上一版的真实课堂样本中，同一个概念属性被同时归入两个类别，部分课堂脚注也只落在关键原句附近。上述修复能提高来源和版本的可核对性。要验证模型的判断，需要按教师原话和教材逐句评阅生成稿。本轮沿用已有真实样本作定性检查，新增测试采用隔离资料与模拟响应。

**首次使用的易用性（N04、A07）待学生试用。** 自动化可以验证“设置 → 课程授权 → 生成 → 采用”这条路径能走通。目前的执行记录不能回答第一次使用的学生能否独立完成它。Windows 真机交付、真实长课录音与真实服务时延也未在本轮重测。
