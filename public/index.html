HOW IT WORKS

模拟规则如何改变结果

群众、程序账号和操作者的操作进入本地服务的模拟队列，并共享同一库存。队列工作数、服务耗时和模拟延迟是可调参数；它们不能代表真实平台或真实用户的网络测量。

人、账号与设备

每个程序购票人可映射多个虚拟账号，同一购票人的多个账号共享一个虚拟设备编号。成功状态按购票人共享，人数统计也按独立购票人计算；这些编号是演示身份，不是真实身份证或真实设备指纹。

四种分配规则

先到先得按服务队列处理顺序竞争。限流去重会对高频账号暴露节流处理。窗口抽签在登记窗口结束后随机排序资格。先售后候补先卖库存，释放或退回的票按服务端候补登记生效顺序递补；重复登记不会增加机会，因此它不是抽签。

订单、退票与队列

获得占位后要手动确认。付款超时会等待占位到期；已付款退票进入待再售池，经过设定延迟后才批次释放。查询只返回查询时可售数，不锁库存。确认、取消和退款都是独立操作。

仿真边界

虚拟参与者的请求在同一 Node 进程内安排，经模拟延迟后进入业务队列；这不是每次独立的真实 HTTP 网络请求。结果不能承诺最后一个请求一定抢到票，也不能证明某一类用户总能赢。状态保存在本地服务内存，重启后清空。
