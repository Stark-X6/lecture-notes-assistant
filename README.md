# 听课笔记助手 Windows 与 macOS 桌面版

这是依据《听课笔记助手系统设计书 v1.0》和本次设计评审意见实现的桌面试用版。课程、材料、音频、转录和笔记保存在本机；外部 AI 通过用户配置的 API 调用。未提供真实供应商账户与密钥，不能将模拟测试视为真实模型内容、费用或延迟验收。

当前版本 **0.1.1**，`通义听悟` 分支已实现阿里云通义听悟实时转写、临时字幕、正式转录、暂停恢复与本地音频补转写。

## macOS 安装与运行

支持在 Mac 上开发与打包；本次适配以 Apple Silicon（arm64）验证。需要 Node.js 22.12 及以上。

```bash
npm ci
npx install-electron --no
npm start
```

第一次点击“开始录音”时允许麦克风权限。若曾拒绝，在 **系统设置 → 隐私与安全性 → 麦克风** 中允许“听课笔记助手”（开发运行时通常为 Electron），然后重新打开应用。使用系统默认输入设备；系统回环收音仍不属于此版范围。

```bash
npm run test:mac       # 权限与 Dock 激活回归，使用模拟音频
npm run pack:mac       # 生成本机架构的 .app
npm run dist:mac       # 生成本机架构的 DMG 和 ZIP
npm run dist:mac:x64   # 为 Intel Mac 构建，需另行在 Intel 设备验证
```

Apple Silicon 的应用目录为 `release/mac-arm64/听课笔记助手.app`，安装镜像为 `release/LectureNotes-0.1.1-mac-arm64.dmg`。DMG 打开后将应用拖到“应用程序”文件夹再启动。当前构建使用本机 ad-hoc 签名，未进行 Apple 公证；对外正式分发时应配置 Developer ID 签名和公证。

关闭最后一个窗口后，Mac 应用保留在 Dock，可再次点击打开；使用 **⌘Q** 退出。录音中关闭或退出仍会按原流程提示或保存并结束听悟云端任务。默认数据位于 `~/Library/Application Support/<应用名称>/library`；macOS 凭据由 Keychain 保护，其他机器或 Windows 的密文不能直接解密，应重新填写 API 凭据。

通义听悟的 AppKey、AK、课程授权和补转写步骤与 Windows 相同，见下文。更多 Mac 验证和打包说明见 [macOS 适配说明](docs/macos-support.md)。

## 从 Gitee 获取并运行（Windows）

需要 Windows 10/11 x64、Git 和 Node.js 22.12 及以上。克隆本分支后在 PowerShell 中执行：

```powershell
git clone --branch 通义听悟 --single-branch https://gitee.com/mastey/hust-se-team.git
cd hust-se-team
npm ci
npx install-electron --no
npm start
```

已有本仓库的本地副本时：

```powershell
git fetch origin
git switch --track origin/通义听悟
npm ci
npx install-electron --no
npm start
```

若本地已经存在 `通义听悟` 分支，使用 `git switch 通义听悟`，再执行 `git pull --ff-only`。

仓库包含源码、测试和文档。首次克隆后按以上步骤启动；Windows 安装包由下方构建命令在本地生成。

## 通义听悟使用步骤

1. **开通服务**：在 [通义听悟控制台](https://nls-portal.console.aliyun.com/) 开通“实时记录”，进入“我的项目”创建项目并取得 **AppKey**。回调方式可以选择“不设置回调主动轮询”。账户准备见 [阿里云快速入门](https://help.aliyun.com/zh/tingwu/getting-started-1)。
2. **准备访问凭据**：取得有听悟调用权限的 **AccessKey ID** 和 **AccessKey Secret**，推荐使用专用 RAM 用户。涉及权限为 `tingwu:CreateTask`、`tingwu:GetTaskInfo`；AppKey 所属项目须允许该身份访问。这里填写阿里云 AK，并非百炼的 `sk-…` 密钥。
3. **创建课堂**：启动应用，新建课程和课次。首次体验也可打开标明用途的示例课程。
4. **保存听悟配置**：停止录音，打开左下角 **API 与设置**，工作模式选择 **真实 API**，语音提供商选择 **阿里云 · 通义听悟**，填写 AppKey、AccessKey ID、AccessKey Secret，选择中文或中英文自由说等语种，点击 **保存 API 配置**。听悟端点由应用配置，无需填写 WSS 地址或转录模型 ID。
5. **授权当前课程**：保存配置后，勾选 **允许发送麦克风音频与本课待补转写分片**，点击 **保存课程授权**。更改提供商配置后须重新授权。
6. **测试并录音**：可点击 **测试听悟鉴权（可能计费）**，确认测试任务成功创建并结束；随后关闭设置并点击 **开始录音**。临时字幕会不断更新，完整句子进入“课堂转录”。鉴权测试不发送录音，实际转写效果通过录音验证。
7. **生成笔记**：需要 AI 笔记时，再配置“文本生成”的 Chat Completions 兼容 HTTPS 地址、模型名称及文本 API 密钥，保存配置并重新保存课程的音频与文本授权。半自动点击 **提交本段**，或切换 **自动 · 60秒**。听悟只负责转写，笔记由独立文本服务生成。
8. **暂停、结束与补转写**：暂停会结束当前听悟任务，继续录音时创建新任务。断线时音频仍保存在本机；停止本课录音后点击底部 **补转写**，按原音频时长补发未确认范围。补转写无需 OSS，期间请保持应用打开。

密钥只在应用设置中填写，由当前操作系统的凭据机制加密保存。云端任务结束失败时，进入设置点击 **重试结束云端任务**。更换听悟项目、凭据或删除课程前，先处理遗留任务。完整说明见 [听悟接入与使用说明](docs/tingwu-integration.md)。

常见情况：

| 现象                          | 处理方法                                                                         |
| ----------------------------- | -------------------------------------------------------------------------------- |
| 应用仍显示模拟模式            | 工作模式改为“真实 API”，保存配置并重新授权课程                                   |
| 提示无音频授权                | 保存当前课程的音频授权；每次更改 API 配置后重新授权                              |
| 鉴权失败                      | 检查实时记录服务是否开通，AppKey、AK ID、AK Secret 是否对应，以及 RAM 权限和网络 |
| 有转录但没有 AI 笔记          | 配置文本生成服务并保存课程文本授权，再提交本段或开启自动整理                     |
| 断网后缺少转录                | 停止本课录音后点击“补转写”；处理速度约为音频原速                                 |
| `npm ci` 或 Electron 下载失败 | 检查 npm/GitHub 下载网络，恢复后重新执行安装命令                                 |

## Windows 安装与启动

安装包位于 `release/LectureNotes-Setup-0.1.1.exe`，解包版位于 `release/win-unpacked/听课笔记助手.exe`。解包版必须保留整个目录。构建未使用商业代码签名证书。

开发环境要求 Windows 10/11 x64、Node.js 22.12 及以上：

```powershell
npm ci
npx install-electron --no
npm start
```

首次启动可创建课程，或主动打开标明用途的示例课程。录音默认使用 Windows 默认麦克风；切换设备请先在系统设置中修改默认输入设备。系统回环收音、板书、OCR、自动找页、卡片、问答不在此版实现范围。

## API 接入

打开左下角 **API 与设置**，工作模式选择“真实 API”，分别填写以下信息。密钥在应用内输入，不要写到源码、README 或聊天里。

| 能力                     | 当前支持协议                                                 | 需要填写                                              |
| ------------------------ | ------------------------------------------------------------ | ----------------------------------------------------- |
| 笔记整理、模板起草与预览 | Chat Completions 兼容 HTTP；支持 SSE 或 JSON 响应            | 完整 HTTPS 端点、模型 ID、文本密钥                    |
| 麦克风实时转录           | OpenAI Realtime transcription 事件协议；24 kHz 单声道 PCM16  | 完整 WSS 端点、转录模型 ID、语音密钥                  |
| 断线音频补转写           | OpenAI 兼容 multipart 文件转写接口，返回 `{ "text": "..." }` | 完整 HTTPS 文件转写端点、模型 ID、语音密钥            |
| 通义听悟实时及补转写     | 阿里云听悟新版任务 API + WSS 二进制音频推流                  | 项目 AppKey、AccessKey ID、AccessKey Secret、识别语种 |

使用通义听悟：停止录音后，在 **API 与设置** 中选择“真实 API”，语音提供商选择“阿里云 · 通义听悟”，填写凭据并保存；随后保存当前课程的音频授权。可先点击“测试听悟鉴权”，再开始录音观察字幕。文本服务独立配置。详见 [听悟接入与使用说明](docs/tingwu-integration.md)。

听悟补转写通过实时接口按原音频时长推送本地未确认分片，无需 OSS；补转写时必须停止本课录音并保持应用打开。暂停和继续分别结束、创建听悟任务；任务失败不影响本地音频保存。云端结束失败会保留任务标识，可在设置中点击“重试结束云端任务”。AK ID 和 Secret 均加密保存，不返回界面快照。

OpenAI 配置中的地址是协议示例，不代表已经为你选定供应商。**文本协议兼容不等于语音协议兼容**；除已适配的通义听悟外，其他厂商专有语音协议仍需单独适配，不能仅替换 URL。所有服务端点拒绝明文 HTTP/WS、内嵌用户名密码和重定向。

保存配置后，在同一页面为当前课程单独授权“转录/选定材料/笔记”和“音频”。切换任何提供商配置会撤销旧授权并取消在途任务。“发送测试文本”调用文本服务；“测试听悟鉴权”创建并结束听悟测试任务，均可能产生调用费用。价格未接入，界面按调用次数及输出 token 上限控制请求，**不承诺金额上限**；实时语音费用应在供应商后台设置预算。

密钥使用 Electron safeStorage，在 Windows 上使用当前账户保护，在 macOS 上使用 Keychain。数据库与原始音频本身没有全盘加密。只有受控主进程读取密钥，界面快照不含密钥。

## 使用流程

1. 新建课程与课次，按需导入 PDF 课件、PDF 教材。只把当前选定页范围的文字提供给 AI；扫描 PDF 可预览，但不会伪造提取结果。
2. 开始录音，或导入 TXT/SRT 转录。课程右上角“…”中可导入 MP3/WAV，随后点击底部“补转写”。TXT 保留段号，不编造时间戳。
3. 半自动模式点击“提交本段”；录音中的未定稿尾部会登记待提交范围。自动模式按有效采集时钟登记 60 秒窗口，等待对应音频范围确认后提交。暂停时不累计采集时间。
4. 勾选转录段，点击“归入主题”，即可修正待归类或错误归属。纠错保留原转录修订，并标记受影响笔记。
5. 笔记支持 Markdown 编辑、阅读和约 800 ms 防抖保存。人工编辑后的 AI 更新进入候选；候选以主题为单位确认。过期候选必须重新生成，历史恢复会追加新版本。
6. 课程模板支持手动编辑、AI 起草、实际课次内容预览、独立复制。保存模板只影响之后创建的任务。
7. 导出读取固定笔记快照，生成 `notes.md`、`sources/` 和 `manifest.json`。来源含材料页或转录时间/段号。当前不自动复制 Markdown 本地图片附件，发现相关引用会明确拒绝导入/导出，不输出缺失附件的“成功包”。

开始录音和停止 AI 相互独立。断网时音频仍保存，可在恢复服务后点“补转写”；补传只处理尚未确认的范围。恢复不会依靠文字相同去重，以免删掉老师的合理重复。

## 数据与恢复

默认目录为 `%APPDATA%/<应用名称>/library（开发运行名称为 lecture-notes-desktop，打包版本可能显示为听课笔记助手）`，内含 `app.db`、`courses/` 和 `lessons/`。如需备份，请退出应用后复制整个 `library` 目录。测试使用 `LECTURE_DATA_DIR` 指定隔离目录，不污染正式课程。

SQLite 当前以单个应用状态快照实现原子持久化，资源文件单独管理。写入采用临时文件、fsync、原子更名，成功后才显示保存完成。启动扫描遗留完整 WAV，补登记已经落盘但未登记的分片；中断任务变为可重试，避免未经确认的重复调用。

删除课程需要输入完整课程名，会撤销访问、取消在途任务并清理关联本地目录。应用外导出文件与供应商持有的数据无法由本地删除自动撤回。

## 构建与验证

```powershell
npm test                 # 核心规则、持久化、API 协议与故障注入测试
npm run build            # TypeScript 检查与界面构建
node tests/smoke.cjs      # Electron 窗口端到端测试，使用模拟麦克风
npm run test:tingwu       # 听悟设置、加密凭据及模拟推流桌面测试，不调用云端
npm run pack:win         # Windows 解包目录
npm run dist:win         # Windows NSIS 安装包
```

端到端测试覆盖创建示例课、模拟整理、人工编辑保护、候选对照、PDF 导入与索引、模板起草预览、来源导出，以及录音暂停、继续、停止与尾部分片。测试数据及截图分别保存在 `.test-data/` 和 `artifacts/`。

详见 [实施说明](docs/implementation.md) 和 [验收清单](docs/acceptance.md)。此版是可运行、可配置 API 的试用实现；90 分钟真实课程、真实设备异常、真实供应商 5 秒转录与 20 秒笔记目标尚需现场验收。
